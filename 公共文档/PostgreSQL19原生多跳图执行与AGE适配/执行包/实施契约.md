# PG19 原生多跳与 AGE：实施契约

本文件把[原设计](../../02.%20PostgreSQL19原生多跳图执行与AGE适配详细设计.md)转成执行约束。它不证明 `graph_adj` 或新图节点已经实现。代码与运行证据优先决定“目前具备什么”；功能目标与硬约束仍以原设计为准。

## 1. 范围和阶段

完整路线保留 G0、GS、G1～G6。首轮是冻结开发基线、最小存储原型、PGQ 固定 2～4 跳。产品化 Phase 2 必须等 GS、G1 同时通过；AGE 首期 fixed MATCH 使用公共内核和已验收 provider，不依赖 AGE memory。

区分以下状态，不把它们折算成一个完成百分比：

| 状态 | 可据此声称的事实 |
|---|---|
| 执行包检查 PASS | 任务、脚本、引用、参考契约与状态工具可用 |
| 开发基线 PASS | 指定基线构建/测试已运行；不代表产品能力 |
| G0 正式门 | 真实业务输入、资源、样本计划和必测组合已冻结，正式基线已跑 |
| GS | 已实现的存储原型通过限定矩阵的正确性及零退化门 |
| G1 | 固定多跳、两层有界批、稳定 ref 接入和最小统计/成本链经独立 oracle 验证，有自然计划和联合回归证据 |
| G2～G6 | 每个阶段按声明能力逐项验收；模板、fallback、内部符号均不代替用户入口 |

正式业务输入未提供时，允许做独立的接口、正确性和诊断原型工作，不宣布 G0/GS 正式通过。此区分只影响开发调度，不减弱原设计的产品准入顺序。非负权 shortest、AGE 写入 clause 优化仍属另行设计的后续项，在任务表中 deferred；有界枚举、复杂模式和高级只读适配保留在完整路线。

## 3. 参考接口到正式实现

[Provider V2](include/graph_provider_v2.reference.h)、[fixed IR V2 参考](include/graph_program_v2.reference.h)、[页字段 V2](include/graph_adj_page_v2.reference.h) 和[统计首版](include/graph_stats_v1.reference.h)是活动接口。Catalog/Result ABI 仍 V1；统计 format 首版 V1，不随邻接 ABI 一起自增。`selfcheck.py` 按 [V2 基线绑定](specs/design_baseline_v2.json)编译活动参考头；它们不是可直接复制落盘的 ABI，更不是图功能。原三个 V1 头及 V1 存储契约只保留作历史证据，不得进入活动任务的实施阅读路线。

正式接口落实规则：

1. C 回调表带 `struct_size` 和 `abi_version`。未知必需能力、版本不匹配在执行前拒绝；不同类别 provider 以 `(kind, owner_extension_oid, name)` 区分。
2. 计划保存 provider identity、代际、类型、列映射和可序列化表达式。回调地址、`EState`、snapshot、MemoryContext、AGE AST、缓存地址不进入缓存计划。
3. snapshot 由 executor 注册并持有；provider 借用。每次请求同时固定 command ID、有效角色、安全上下文、关系锁和 catalog generation。
4. `begin` 复制 endpoint 数组到 scan context；`next` 返回的 item 只保证活到下一次 next/rescan/end。需要跨批保留的按 PG 类型元数据复制到 binding context。
5. `next` 返回 `0..capacity`；0 是 EOF。开始执行后的失败使用 PG ERROR；不得把负值当“去跑 fallback”。正常结束一次 end；ERROR/cancel/ResourceOwner 清理必须覆盖所有 pin 和临时文件。
6. item 是物理候选。公共层通过正确 Table AM 索引取元组接口追随 HOT，执行边和顶点各自的可见性、RLS/权限与 quals；回表不能弥补 provider 漏候选。
7. 首版 `GgcOpenRequestV2` endpoint 限 int8 非空，带 request ID 和可选 scoped handle；非覆盖 B-tree 的 opposite key 可等 Table AM 回表后取得，缺失不等于 key=0。通用键/NULL/复合键在 G2-070 扩展验收。
8. 新 capability 初始关闭。成本参数没有标定数据时不能编造数字宣称自然 CBO 胜出；诊断计划选择与正式性能成绩分开记录。
9. key 目录只解析入口/跨 scope 或非权威 hint 回退；同 scope 的稳定 ref 直达 Slot。目录 split 不移动 live Slot，同 scope 持久化 ref 冲突直接 ERROR，不能目录回退掩盖损坏。
10. 公共两层批管理 candidate/parent/原序号、页调度与恢复，各有条数/字节/页/pin 上限及取消路径。Slot/小 Base/Delta 从首版 packed，空方向不预分配数据页；owner/lane/cutoff/next 是段级字段。
11. estimate 与 executor open 请求分开：估价只读有界 profile，不需要 EState、遍历全图或构建 AGE cache。逻辑 E、物理 X、Table AM H 和页组/IO 分别估计。

首期 fixed IR 的必需字段由原设计 §5.1、§6.2 提供，落地时按下表补齐结构而不是只复制伪代码：

| 对象 | 必需实现内容 |
|---|---|
| provenance 节点 | NodeTag、版本、前端/provider identity、graph OID、relation/RTI/Var 映射、局部/跨变量/安全 quals、输出映射、required_outer、scope IDs、semantic fingerprint |
| variable/element 节点 | 稳定变量 ID、vertex/edge 角色、实际 relation OID、key AttrNumber、类型/opfamily/collation、原 Var 与结果 slot 映射 |
| fixed hop 节点 | input/edge/output variable ID、方向、关系/列映射、必需变量集合、所属 uniqueness scopes、quals；不嵌物理 provider 指针 |
| fixed program 节点 | 版本、前端、结果模式、通用有限 `N` 个显式 hops、完整 hop 列表、stage_order、output_map、required_outer、catalog generation；1～4 只是当前基线样例，不进入结构上限 |
| plan / plan state | 前者只有序列化程序/访问参数和预算；后者持有回调、snapshot、ExprState、scan/binding context、资源计数 |

固定线性子集先使用单个有向关系类型、明确 OUT/IN 与 int8 key；PGQ WALK 与 AGE clause 内 TRAIL 分开验证。重复 endpoint 可以合并探测请求，不能合并 binding。核心候选尚不支持的多 label、外连接或安全边界整体拒绝；普通 SQL fallback 使用实际存在的索引。

PG19 节点支持主要由 `src/backend/nodes/gen_node_support.pl` 生成。G1-010 必须检查 `node_headers`、Makefile 与 Meson 接入、生成属性及需要的 custom 支持，覆盖 copy/equal/out/read/query jumble。不能只修改 `copyfuncs.c`，也不直接编辑生成的 `*.funcs.c` 或 `nodetags.h`。跨版本不承诺旧 cached plan 二进制 ABI。

## 4. 首批可运行输入与正确性

[small_graphs.json](golden/small_graphs.json) 包含手工预期的菱形、平行边、自环、闭环、零跳和长度下界反例；[oracle.py](scripts/oracle.py) 穷举完整路径历史，不复用生产 visited、剪枝或双向终止算法。限定 8 hop，供小图验证，不承担大图基准。

[check_baseline.py](scripts/check_baseline.py) 已提供：普通 SQL、PGQ WALK、AGE TRAIL 的三方检查；1～4 hop、OUT/IN、重复 binding、平行边和 NULL/text 投影。比较完整 multiset，不能转为 set，也不能仅比较 count。AGE graphid 与业务 `key` 不混作同一身份；当前跨前端比较分别根据各自模式生成 oracle，不伪造 WALK=TRAIL。

搜索模式的 16 个手工样例包含 ALL shortest 与有界 reachability，但当前 SQL/PGQ 新搜索语法尚不存在，因此这些首先只是参考实现测试。G4 的验收必须新建真实语法入口并执行独立 oracle；不能把本包 oracle PASS 记为 PG19 搜索算子 PASS。

后续每张卡的 `checks/<TASK_ID>.py` 是该卡必须交付的独立验收程序；当前不存在即明确报 NOT_IMPLEMENTED。最后一行输出 JSON：`task_id`、`status`、完整 `assertions_passed`、带 SHA 的 `evidence_files`；需要新能力实际执行的任务另给 `selected_feature_plan_evidence`。测试须运行原生回归/隔离/故障场景并输出日志，不能仅检查文件存在或打印 PASS。

参考结果不从候选自动生成。调整既有 expected 前逐项审查失败 SQL、错误种类、类型、顺序契约和版本差异，记录理由。不能一键复制全部 results 到 expected 来消除红灯。

## 5. 性能协议

[acceptance.json](specs/acceptance.json) 中 development 是已明确命名的开发配置：1 万顶点、8 万边、固定 seed、1/4 客户端、10 秒×3 轮、持久性开启。它验证编排和采样，不能达到正式持续维护要求；单机内存约 8 GB，不声称已覆盖千万顶点和超缓存矩阵。

`benchmark.py` 实际生成 CSV、建立 PK/FK 和窄 OUT/IN B-tree，记录实际 `pg_index` 定义、有效性、配置、查询计划、pgbench 命令及每事务原始延迟。每次采样重建本实验 schema，完整消费两跳查询结果。当前只覆盖普通 B-tree 和单行 autocommit 写入，不模拟不存在的 graph_adj。

正式 product 中所有 null 项必须填入真实输入，status 改为 FROZEN 前保留一次可核对的决定与配置摘要。应在候选性能数据产生前冻结必测组合、样本计划、请求速率、资源、停止规则；不得因结果慢删除组合或把零容忍改成 3%/5%。本包预设的统计方法/下限是待正式预注册确认的执行选择，不改变原设计零退化门。

`performance.py` 接受独立成对轮次格式：

```json
{"schema":"paired-independent-rounds-v1","preregistered_metric_count":3,"cases":[
 {"id":"one_case","rounds":[
   {"pair_id":"round_01","baseline":{"successes":20000,"throughput":1000,"p95_ms":4,"p99_ms":8},
    "candidate":{"successes":20000,"throughput":1100,"p95_ms":3.5,"p99_ms":7}}
 ]}
]}
```

示例只有一轮，必定不足以签收。分析器按独立轮次的 log ratio 重采样，输出几何均值比的单侧界；对预注册的全部组合×指标做 Bonferroni。每轮 P99 少于 1 万成功请求、独立轮次少于 20 时 INCONCLUSIVE；这里的下限不能替代正式功效/样本量分析。bootstrap 尾部分辨率不足会拒绝，需在采样前调整重复数。不能把事务条目当独立实验轮，也不能混用同一闭环饱和测试的 P99 作为固定到达速率门。

该工具的 `metric_status` 只评价输入数值，不验证上游实验真实性；`product_gate` 固定为 NOT_EVALUATED。正式门还要校验原始请求/重试、计时边界、等资源、必测组合完整性、维护时间序列和功能/安全证据。bootstrap 区间接近边界时必须保留 INCONCLUSIVE；性能门不能由模型反复采样直到碰巧过线。

## 6. 任务、状态与证据

[tasks.json](specs/tasks.json) 是唯一任务定义，[task_state.json](state/task_state.json) 是唯一进度账本。每卡含依赖、设计阅读范围、源码锚点、允许路径、assertions、验证命令和停止条件。新模型只加载核心契约及活动任务所需章节，避免每次把全部设计重新塞入上下文。

`taskctl.py claim` 只领取依赖完成的任务；同一时刻一个 active task。`run` 用参数数组执行验证命令，保存真实退出码、日志 SHA、任务定义和实现摘要。`complete` 检查证据齐全及未过期；失败、改过日志、验证后改过实现不能通过。`block` 记录理由并释放 active，独立任务仍可推进；`reopen` 会使已完成的下游依赖失效。

V2 用 `sync-definitions --reason` 追加 9 个 todo，不重置账本；5 项 completed 的定义与 evidence 条目不变。该命令拒绝活动任务、删除历史 ID、改变 completed 定义和依赖环，不自动完成新任务。包校验同时检查设计摘要、V2 引用和必要前置链；主设计变化后须审阅对齐再绑定摘要，不能跳过漂移检查。

历史 completed 证据对应完成时的实现摘要。后续任务合法修改共享文件时，历史日志仍有效，但不等于新版本自动通过旧阶段门；阶段集成检查须用当前完整构建重跑。完成动作检查当前文件，历史账本校验检查原始日志与任务定义，避免共享文件正常演进使所有历史记录无故失效。

状态工具提供一致性检查，不代替代码审查；有权限修改工具的执行者仍必须遵守证据契约。常规实现选择在已授权范围内自主处理；不得把每个原子任务变成人工批准点。业务指标变更、扩大支持范围或索引迁移等实质变化应先形成可审查方案并记录用户决定。

## 7. 退出和交付

每阶段报告“已实现能力、实际新计划、值/类型/多重性、错误与资源行为、基准配置、原始日志、PASS/FAIL/INCONCLUSIVE、未实现范围”。关闭 feature flag 不代表移除了物理索引维护。AGE 仍失败的基线项要在进入受影响阶段前关闭，不能以“历史问题”永久豁免产品门。

没有实际实现的 `graph_adj`，GS 就是 NOT_RUN；没有真实业务 SLO，正式 G0/查询门就未完成。这些事实必须出现在恢复断点和最终报告中，不影响诚实交付已完成的执行准备工作。

## 8. 统计与成本模型的最小闭环

按[统计契约](specs/graph_statistics_v1.md)实施：G1-015 目录/发布 → G1-025 单跳/零度/热点 → G1-046 短路径与物理 profile → G1-048 有界读取/校准/反馈 → G1-050 自然 CBO；G1-075 验证并发、安全、失效与资源，G1-080 验收留出集。G2-040 只扩展自动维护与长路径。

区分均匀顶点、沿边到达、热点与查询反馈总体；OUT/IN 或物理副本不重复计逻辑边。截断保留下界，零行不等于 unknown，observed_max 不作硬上界。统计不能替代 MVCC/完整性/RLS/spill 证明。

采集器通过 Table AM/低层 provider 独立运行，不依赖 GraphPath 获胜。带 `requires_maintenance_execution`/`requires_statistics_evidence` 的任务须附真实维护 SQL/目录事务/权限日志和统计原始测量摘要，分别用 `maintenance_execution_evidence`/`statistics_evidence` 记录路径与 SHA，不能只验证字段存在。runner 校验摘要不自动证明内容真实，独立断言和代码审查仍必需。

采集、反馈和刷新有有限预算并进入 DML 混合负载；不逐边更新全图直方图，不在 planner/autovacuum ANALYZE 内无界展开。既有 `performance.py` 做实验显著性分析，与图优化器统计实现是不同能力。
