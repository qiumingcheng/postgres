基线差分检查的是现有 PGQ 与 AGE 各自语义：PGQ WALK、AGE TRAIL，均与独立路径穷举及对应普通 SQL 的完整 multiset 比较。它不说明两个前端在所有语义上相同，也没有执行新 Graph 节点。

## AGE 六项失败及入口修正

首次回归暴露脚本数据库名问题：PG19 测试入口没有默认建立 AGE 用例要切换的 `contrib_regression`，造成 scan 中断及后续污染。执行包已显式传入正确数据库名，先前日志保留供审计，不能当作最终失败清单。

修正入口后仍存在以下差异：

| 用例 | 已观察事实 | 后续工作 |
|---|---|---|
| expr | 不存在或参数数量不匹配函数的错误消息变化 | 按 PG19 行为逐条审查 expected |
| cypher_match | 四行路径物理顺序不同，另有错误消息变化 | 核对无序语义和 bag，必要时稳定测试排序 |
| cypher_call | HINT 消失或变成 DETAIL | 核对错误行为并适配版本预期 |
| jsonb_operators | 算子错误 DETAIL/HINT 不同 | 审查是否仅版本消息变化 |
| subgraph | 动态 SQL 中不存在算子的错误消息变化 | 审查上下文和错误种类 |
| age_upgrade | 合成升级执行失败：`load_labels_from_file` 相同参数签名已存在，升级成功标志为 false | 单独调查升级模板/初始版本选择，修复后重新验证升级 |

这些项目没有被自动豁免，也没有批量复制 results 覆盖 expected。[known_issues.json](baseline/known_issues.json)保存观察、日志 SHA 和责任任务 `G0-035`。G0-030 的验收是“执行并分类基线”，其完成不等于 AGE 43 项通过；AGE 适配阶段显式依赖 G0-035。

进一步核实 AGE 原始仓库为 shallow clone，当前只有 1 个可达提交；Makefile 的合成升级用 `git log -- age.control` 选择起点，此时返回当前 HEAD。因此 G0-035 应先核实并提供正确的历史初始版本输入。当前合成升级失败不能直接推断所有真实历史升级都失败，也不能因缺历史而标记升级验收通过。

候选首次全量构建在会话中断时未留下完成摘要，后续从该专属构建树恢复并完成构建/安装。对应首次运行保留为中断记录；本次候选成绩按恢复构建报告，不冒充另一次从空目录完成的正式阶段门。baseline 的首次隔离全量构建已完整结束。
