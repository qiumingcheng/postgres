# CLAUDE.md

This file provides guidance to AI coding agents when working with this repository.

## Project Overview

PostgreSQL 9.2.4 with an experimental **Cascades Optimizer**. The Cascades optimizer is in `src/backend/optimizer/cascades/` and integrates with PostgreSQL's standard planner via `planner_hook` (registered in `planner()` at `planner.c:124`).

### Architecture Mode

Cascades imports Paths generated by PG's `make_one_rel()` (**IMPORTED_PATH**) and optimizes upper operators (Agg, Sort, Limit, Project) via its own task scheduler (**COMPOSABLE_OP**). JOIN enumeration is delegated to PG's DP/GEQO — Cascades imports the resulting paths.

**Key constraint**: Do NOT modify PG's `RelOptInfo`, `Path`, or `PlannerInfo` after `make_one_rel()`.

## Module System (vtable dispatch)

Each module registers operator vtables + rules via registry in `pg_module_*_init()`:

```c
// Operator vtable (cost/build/stats callbacks)
pg_registry_register_operator(&(PgOperatorVtable){
    .op = PG_CASCADES_PHYSICAL_SORT, .name = "Sort",
    .cost_fn = pg_cost_sort_fn,       // NULL → default cost 0.01
    .build_plan_fn = pg_build_sort_fn, // NULL → IMPORTED_PATH delegation
    .derive_stats_fn = NULL,           // NULL → default derivation
});

// Implementation rule
pg_registry_register_rule(PG_RULE_MEMO_IMPL, "LogicalSort→PhysicalSort",
    PG_CASCADES_LOGICAL_SORT, PG_CASCADES_PHYSICAL_SORT,
    g_pat_leaf1, pg_rule_sort_to_physical_sort, 1.0, PG_RULE_BIT_SORT_TO_SORT);

// Transformation rule
pg_registry_register_rule(PG_RULE_MEMO_TRANSFORM, "PruneSortColumns",
    PG_CASCADES_LOGICAL_SORT, 0, NULL, pg_rule_prune_sort_columns,
    0.5, PG_RULE_BIT_PRUNE_SORT_COLS);
```

### Rule Categories (3 buckets in registry)

| Category | Description | Consumers |
|----------|-------------|-----------|
| `PG_RULE_PRE_MEMO` | Pre-Memo rules (g_pre_memo_rules[]) | cascades.c only |
| `PG_RULE_MEMO_TRANSFORM` | Transformation rules (Phase 3/5) | rewrite.c, task.c |
| `PG_RULE_MEMO_IMPL` | Implementation rules (Phase 1/2/4) + Enforcer | task.c only |

### Vtable dispatch locations

| Location | Code | Trigger |
|----------|------|---------|
| `core/task.c:1149` | `vt->cost_fn(...)` | `expr->op >= PG_CASCADES_PHYSICAL_HASHAGG` |
| `core/planbuild.c:316` | `vt->build_plan_fn(...)` | `expr->op >= PG_CASCADES_PHYSICAL_HASHAGG` |
| `core/memo.c:575` | `vt->derive_stats_fn(...)` | All ops |

### Build wrapper child selection (2-pass — critical)

All `pg_build_*_fn` use two-pass to prefer COMPOSABLE_OP (Project) over IMPORTED_PATH (Scan):

```c
// Pass 1: prefer COMPOSABLE_OP (ensures column projection)
foreach(lc, child_group->best_entries) {
    if (child_required_props != NIL &&
        e->expr->mode == PG_PHYS_EXPR_COMPOSABLE_OP &&
        pg_required_property_equal(...))
    { child_best = e; break; }
}
// Pass 2: fallback to any match (IMPORTED_PATH)
if (child_best == NULL) { /* any match */ }
// Ultimate fallback: first child in list
if (child_best == NULL)
    child_best = linitial(child_group->best_entries);
```

## IMPORTED_PATH vs COMPOSABLE_OP

| Aspect | IMPORTED_PATH (mode=0) | COMPOSABLE_OP (mode=1) |
|--------|----------------------|------------------------|
| Source | PG `make_one_rel()` Paths | Cascades impl rules |
| op_private | `Path *` | Operator params |
| Inputs | NIL (self-contained) | `List<Group *>` (child groups) |
| Cost | Read from Path.total_cost | Computed via PG cost functions |
| Plan extraction | `create_plan(root, path)` | Recursive → wrap with PG `make_*()` |
| Used for | Scan / Join | Upper ops (Agg, Sort, Limit, Project) |

## Key Bug Fixes (important context)

### Bug 1: Registry list nodes in planner context (SIGSEGV)
`pg_registry_register_rule()` used `lappend()` in current context. List nodes were freed after first query. **Fix**: `MemoryContextSwitchTo(TopMemoryContext)` before list construction.

### Bug 2: JOIN empty targetlist → "attribute N has wrong type"
`pg_cascades_fix_empty_targetlists()` treated JOIN empty targetlist as "corrupted Path". In reality, `count(*)` needs no columns → PG sets NIL targetlist. **Fix**: Propagate child targetlist to JOIN node.

### Bug 3: Inner plan lacks Project → SubqueryScan type mismatch
Cascades plan extraction selected IMPORTED_PATH Scan over COMPOSABLE_OP Project. Scan outputs 4 columns, outer SubqueryScan expects 3. **Fix**: 2-pass child selection preferring COMPOSABLE_OP (see build wrapper pattern above).

### Bug 4: JOIN_SEMI → "unrecognized join type: 4"
`pull_up_sublinks()` generates JOIN_SEMI JoinExpr, PG 9.2's `deconstruct_jointree()` doesn't handle it. **Fix**: `pg_fix_semi_join_type()` converts SEMI/ANTI → INNER after sublink conversion. SEMI semantics preserved in WHERE EXISTS clause.

### Bug 5: Fallback reuse of prep->final_rel
Setting `prep->lower_paths_built=false` caused second `make_one_rel()` on polluted state → "failed to build N-way joins". **Fix**: Reuse `prep->final_rel` from first `make_one_rel()` (paths are valid).

|--------|---------|-----------|

## Conventions

- **No `static` for cascades functions**: gcov needs non-static for coverage tracking
- **Debug macro**: Use `CASCADES_DEBUG(flag, "CASCADES: ...", ...)` — never inline `if (debug) elog()`
- **Module files**: Keep building wrappers in expanded form for readability (sort.c, agg.c, limit.c, distinct.c, project.c). Transform functions may remain compressed.
- **Planbuild default**: `default: return NULL;` — never `elog(ERROR)` for unrecognized op. Graceful fallback is critical.
- **Registry list nodes**: MUST be in TopMemoryContext — use MemoryContextSwitchTo before lappend in pg_registry_register_rule.
- **Plan extraction**: `pg_cascades_fix_empty_targetlists()` is called inside `pg_cascades_extract_best_plan()`. It fixes empty/mismatched targetlists across the ENTIRE plan tree including SubqueryScan subplans.
